BMA Sistemas · 2025 – hoje

Provisionamento e plataforma de clientes

Construí do zero uma ferramenta de provisionamento automático de clientes em C# (Windows Forms) com integração ao Active Directory, que levou o processo de 45 para 3 minutos (−93%). Depois integrei a ferramenta à biblioteca de clientes: ao liberar um ambiente, a plataforma web se atualiza sozinha, sem etapas manuais duplicadas.

Entre os desafios técnicos resolvidos: inconsistência de codificação de caracteres entre o arquivo de configuração e o restante do pipeline, uma lógica de backup que não detectava registros duplicados corretamente, e um ponto de sobrescrita de dados posicionado no lugar errado no serviço. Também mapeei que um erro de identidade não mapeada era uma questão operacional — o usuário de rede precisa existir previamente — não um defeito de código.

Também criei a aplicação web da biblioteca de clientes, que tirou as informações do servidor e levou o acesso de 4 para 25 colaboradores; desenvolvi front e back do módulo de banco de horas do novo Portal Web a partir do legado; e montei um dashboard em Supabase (PostgreSQL) com apuração de ponto em tempo real para mais de 1.000 clientes, onde antes cada consulta levava 5 minutos.

Implementei uma tela de monitoramento de integrações que envia e-mail automático quando há erro, para as falhas serem detectadas mais cedo, e sustento a operação com SQL Server, PostgreSQL e MySQL, além de ODBC e IIS.

Entregas

  • Ferramenta própria em C# (Windows Forms) com Active Directory: provisionamento de 45 para 3 minutos
  • Integração com a biblioteca de clientes: ao liberar um ambiente, a plataforma web se atualiza sozinha
  • Aplicação web da biblioteca de clientes: acesso de 4 para 25 colaboradores
  • Módulo de banco de horas do novo Portal Web, front e back, a partir do legado
  • Dashboard em Supabase (PostgreSQL) com apuração de ponto em tempo real para 1.000+ clientes
  • Tela de monitoramento de integrações com e-mail automático quando há erro
  • Sustentação com SQL Server, PostgreSQL e MySQL, ODBC e IIS

Trecho ilustrativo do meu estilo de código — não é código de produção real da empresa.

public async Task<ProvisioningResult> CreateUserAsync(ProvisioningRequest request)
{
    if (string.IsNullOrWhiteSpace(request.NetworkId))
        throw new ArgumentException("Network ID é obrigatório.", nameof(request));

    _logger.LogInformation("Iniciando provisionamento para {NetworkId}", request.NetworkId);

    if (await _directory.UserExistsAsync(request.NetworkId))
    {
        _logger.LogWarning("Usuário {NetworkId} já existe — abortando.", request.NetworkId);
        return ProvisioningResult.Skipped(request.NetworkId);
    }

    try
    {
        await _directory.CreateUserAsync(request);
        _logger.LogInformation("Usuário {NetworkId} provisionado com sucesso.", request.NetworkId);
        return ProvisioningResult.Success(request.NetworkId);
    }
    catch (DirectoryOperationException ex)
    {
        _logger.LogError(ex, "Falha ao provisionar {NetworkId}", request.NetworkId);
        throw;
    }
}

SZ Soluções · 2023–2025

Automação de pipeline de KPIs

Na SZ Soluções, o envio de dados para os indicadores de atendimento era feito manualmente — processo lento e sujeito a falhas humanas. Automatizei todo o pipeline em C#, eliminando 100% da entrada manual de dados e garantindo atualização contínua dos indicadores sem intervenção humana.

Com os dados já consolidados automaticamente, passei a entregar mensalmente dashboards em Power BI e Looker Studio — médias, volumes e SLAs — diretamente para a gestão e diretoria da empresa contratante.

Também executei queries SQL/MySQL para extração e validação de dados em investigações técnicas, auditorias de SLA e suporte especializado no ERP TOTVS Datasul.

Também gerenciei chamados no ServiceNow dentro dos SLAs, com triagem, priorização e ponte entre usuários e desenvolvimento.

SENAI · 2022–2024

Sistema de Gestão Comercial

Desenvolvido durante o curso técnico no SENAI (2022–2024), este sistema cobre o fluxo operacional completo de um pequeno comércio: abertura e fechamento de comandas/pedidos, controle de estoque, fluxo de caixa e emissão de relatórios gerenciais para apoiar decisões do dia a dia.

Um dos pontos técnicos mais interessantes foi a integração de leitura de código de barras ao fluxo de vendas, permitindo lançamento rápido de itens e baixa automática no estoque — tudo persistido em um banco MySQL centralizado, garantindo que comandas, estoque e caixa nunca ficassem dessincronizados.

O projeto foi construído com JavaScript e PHP no back-end, refletindo minha entrada no desenvolvimento antes de migrar o foco principal para .NET — uma base que ajuda a entender diferentes ecossistemas de servidor.

Módulos

  • Comandas e pedidos com lançamento de itens
  • Controle de estoque com baixa automática via código de barras
  • Fluxo de caixa (abertura, movimentações, fechamento)
  • Relatórios gerenciais sobre banco MySQL centralizado

Front-end · este portfólio

Este site

O portfólio que você está usando agora é a prova de front-end — não uma descrição dela. Construído do zero, sem frameworks: HTML, CSS e JavaScript puro, com foco em performance e em técnicas modernas de plataforma web.

O conceito de "horizonte de eventos" guiou cada decisão: um buraco negro desenhado em canvas 2D, sem bibliotecas, com estrelas desviadas pela gravidade, disco de acreção e partículas que caem em espiral a cada clique. Os projetos são puxados pelo buraco negro antes de abrir.

Inclui sistema de tradução PT/EN próprio, modo condensado para recrutadores, modo calmo com prefers-reduced-motion e estados de foco visíveis — acessibilidade não foi tratada como opcional.

Técnicas usadas

  • Canvas 2D com requestAnimationFrame e devicePixelRatio limitado para poupar o celular
  • Movimento reduzido: a animação desacelera em vez de parar
  • Deep links #case1 a #case6 com painel acessível (Esc devolve o foco ao card)
  • Sistema de i18n (PT/EN) escrito do zero, sem biblioteca
